## Publishing and offline use

The existing B2/Cloudflare static build publishes the engine, stylesheet,
illustration, license and `office-pack.json` under a sealed release directory.
The Java static adapter serves the same generated engine/CSS/art/license files.
The engine is excluded from compulsory service-worker precaching, so visiting
the normal site does not download the building. An explicit offline-save action
checks its byte count and SHA256 against the versioned manifest before storing
it in a scope and release-specific optional cache. The service worker reads only
that release’s saved building and removes obsolete packs on activation. The
ordinary installed shell already contains the room directory and stories.

The office consumes the existing `/fizzbuzz/explained` and
`/fizzbuzz/window/explained` dossiers supplied by `RuntimeClient`; it adds no
business API endpoint. Static-manifest fetching is ordinary same-origin asset
loading. Analytics still omit mandate inputs and share query parameters.
