# ADR 0026: Prior Work Ratification and Institutional Memory Court

## Decision

Every cached body must receive five swappable Java approvals before HIT:

| Office | Actual review |
| --- | --- |
| Precedent Admission Office | Non-null text, at most 10,000 UTF-16 characters |
| Mandate Jurisdiction Chamber | Requested limit 0–1000 agrees with repository key |
| Completeness Inventory Office | Exactly the requested complete nonempty lines and native separators |
| Independent Lexical Bench | Existing independent proclamation notary certifies each ordinal and exact line |
| Non-Performance Licensing Authority | Bound predecessor chain and lexical reinspection |

The final Certificate of Authorized Non-Performance binds the exact immutable
petition through object identity. Equal labels confer no transferable permission.
The directorate checks returned predecessor identities and enforces lexical
validity after the replaceable licensing provider returns. A rubber-stamp
provider therefore cannot circumvent the publication invariant. Zero's empty
body is valid; no nonzero mandate can reuse it. The independent notary and
mathematical test oracles retain their separate implementations.

## Cache and failure behavior

The same court surrounds Redis and IndexedDB. Their existing raw strings/rows
and expiry policies remain compatible. The court never renews TTL or invents
an expiry timestamp. Extended BigInteger windows retain their transient bypass.

A substantive objection returns MISS with a REJECTED dossier and increments
both misses and rejectedPrecedents. The ordinary dispatcher invokes production
at most once and may replace the rejected entry with its real result. Court or
repository infrastructure failures retain the BYPASS/error policy. Unknown
completed mutations are never retried to obtain evidence. Prior audit history
is preserved.

CacheLookup carries the invocation's immutable dossier. Five decisions include
NOT_REACHED for offices that never convened. An optional ASCII
X-SlopBuzz-Precedent-Trace header is limited to 8192 characters; explained JSON
also exposes precedent, or null. Current decisions enter the request-local
execution observer. The papers are never stored in the numerical cache/journal.
Reuse validation performs work but invokes no production strategies, recruitment,
glyph procurement, numerical audit transactions or numerical queue deliveries.

## Public demonstration

The Executive Chronicle narrates current reuse decisions without claiming to
possess the cached answer's original production receipts. A full court desk below
the advisory inventory exposes native disclosures for all five offices, their
rules, received papers, findings and issued documents. Restoring the latest
mandate case after a rehearsal does not rerun business or move chronicle reading.

GET /precedent/rehearsal supports approved, zero, wrong-mandate, missing-line and
lowercase-fizz as exact scenario values. Omission defaults to approved; encoded,
unknown, repeated or extra values return 400. Unsupported methods return 405
with Allow: GET. A substantive rejection returns 200 with REJECTED and later
offices NOT_REACHED. These fixed specimens exercise the same authorities without
reading/writing the real cache or generating numerical audit entries.

The read-only desk may run in the current release's transient worker beside an
older journal owner. No lock is stolen or journal migrated. Older missing papers
receive an honest provenance explanation. OpenAPI drives selectable scenarios
in the human API guide. The desk works offline and through the JVM HTTP adapter.

## Validation

Three hearings for each limit 0–1000 cover exact approval, wrong-key rejection
and independent lexical rejection. Further tests try borrowed/null documents at
every office, dishonest inventories, colluding rubber stamps, concurrent cases,
malformed text and bounded ASCII headers. The portable objection tribunal runs
in both browser compilers. Parity compares all scenario and admission contracts,
current headers and explained envelopes. Browser tests cover poisoned, expired
and raw legacy entries, zero, unchanged audit digests, one production run after
rejection, restored inspection, offline/API controls, old-owner overlap, the
optional JVM UI and accessibility/reflow.
