# ADR 0025: Executive Chronicle of Numerical Affairs

## Decision

Official Output displays the numerical transcript first. The Executive Chronicle
below it has a fixed viewport height at each screen size, independent of the
number or length of entries. New entries follow the bottom by default. Visitors
can stop following and inspect an earlier ordinal without subsequent playback
changing that reading position. The desk pins within the viewport when its full
height fits; zoomed or short viewports retain natural document flow. Mobile order
is controls, output and chronicle, then advisory inventory. Detailed HR case papers
occupy a native modal dialog rather than vertical space ahead of the answer.

Numbers and their narrative advance together. A completed HR case no longer adds
seven preliminary reading delays. Service response time remains separate from
ceremonial disclosure. Pause, stop, immediate disclosure, replay and step-through
operate on the retained result. Replay and inspection submit no new business call.
The story begins with observed One reporting for duty as soon as 1 is disclosed.

## Evidence contract

`ExecutionObserver` is a swappable observation interface. `ExecutionCustody`
provides nested, request-scoped ThreadLocal custody and an exact decimal-string
ordinal context. `ExecutionEvent` is immutable. The default path allocates no event
objects; hot paths avoid constructing detailed messages when no observer exists.
Observer exceptions do not authorize, veto or retry a business operation.
`BoundedExecutionLedger` retains at most 50,000 events and reports omitted counts.

Existing Java authorities emit semantic observations after performing their work:
cache lookup, HR decisions, continuation ballots, factory-appointed contexts,
classification votes, visitor/printer selection, glyph requisitions and delivery,
individual receiving certificates, assembly, transaction staging, independent
notarial verification, publication, audit append, message publication and succession.
Queue acknowledgment is recorded only when a consumer actually accepts a message.
Enqueuing is not described as acknowledgment. Extended BigInteger windows report
their actual classification, procurement, lexical verification and arithmetic
advance without claiming bounded-integer certificates or retained transactions.

`GET /fizzbuzz/explained` and `GET /fizzbuzz/window/explained` wrap one dispatch
to the existing operation in an observation scope. The structured response has
schema `slopbuzz-execution/v1`, the identical original text, optional actual
personnel evidence, and the bounded trace. Error status and original error text
are retained. The plain-text APIs, cache entries, numerical audit schema and
independent oracle are unchanged. Neither a second execution nor a demonstration
is presented as evidence of the original mandate.

## Capability and release overlap

The runtime identity advertises optional `narrative: 1` support. The client probes
before choosing an explained or established plain-text operation. It never
retries a potentially completed mandate to obtain a dossier. Runtime identity
inspection is allowed in read-only transient workers; the narrated extended
window joins that whitelist. Narrated retained mandates do not.

An older persistent worker keeps its single journal and returns its original
answer. Missing personnel records do not become a prominent failure panel.
Narration acknowledges the observed result and labels procedure explanation
separately from actual Java records. It never invents seven historical approvals.
A current read-only personnel rehearsal remains a separate, explicitly labeled
exercise. Cache hits likewise report memory reuse without a new workforce.

## Finite presentation and accessibility

TypeScript narrates the Java evidence; it does not calculate the business answer.
Exact ordinals remain strings. The interface retains the latest 1,000 line dossiers
and renders at most 24 chronological line articles, plus bounded operating notes.
An archive inspection is a separate stable copy; it is not appended as the newest
chronological event. Choosing Latest removes that inspection and restores the
latest announcement and scroll position. Realtime batches narration and leaves
the browser responsive between finite windows.

The named chronicle region handles scrolling for long prose and document text.
Following is optional; resize preserves the bottom when following is enabled.
Automatic following additionally requires the reader to be at the bottom, within
four CSS pixels for fractional scroll positions. Wheel-up, upward keyboard
navigation, touch movement and scrollbar manipulation suspend it before queued
layout work can reposition the reader. Returning to the bottom automatically
discloses pending minutes when the checkbox remains enabled. The observer that
measures layout no longer scrolls on every notification. Explicit checkbox-off
and archive inspection continue to require an explicit return to Latest/following.
Only concise current-action summaries are live-announced. Native details expose
department records, and the native HR dialog has explicit close/Escape behavior
and returns focus to its opener, including WebKit mouse activation.

## Validation

Chronicle language has 420 templates across 35 situation-specific phrase pools
and a rotating pool of 32 general corporate asides. Shuffle bags choose each template before
repeating it and avoid an immediate repeat across bag boundaries. The exact
recorded findings remain literal in every variant; presentation randomness never
changes Java decisions, output or retained evidence. A folio keeps the wording
chosen on its first rendering, so archive inspection, re-rendering and replay do
not rewrite a paragraph while somebody is reading it. Rehearsal paragraphs are
likewise retained for the life of their case object. Phrase tests exhaust every
pool, preserve hostile literal text, and check the no-repeat policy; browser
tests compare original, inspected and replayed prose and unchanged documents.

JVM checks cover single execution, output identity, actual event order, glyph
allocation identity, honest cache/zero/extended paths, observer failure isolation,
finite collection, nested and concurrent custody, error status and JSON escaping.
Exact JVM/browser fixtures include the new structured APIs in both compiler targets
and all three browsers. UI checks cover fixed height, newest-bottom following,
first-line narration, inspection during ongoing output, chronological restoration,
bounded history, replay without new audits, native modal focus, actual legacy-owner
overlap, offline operation, JVM mode, enlarged text and accessibility rules.
