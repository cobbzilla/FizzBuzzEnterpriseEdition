Accessibility

Participation in numerical governance should not depend on how you see, hear, move, or browse. We design this showcase toward WCAG 2.2 Level AA and use native HTML controls with appropriate accessible names and states.

Navigation and reading

  • Press Tab to reveal “Skip to main content,” then Enter to bypass the shared navigation. In Safari, enable keyboard navigation in browser settings or use Option+Tab to include links.
  • Use Tab and Shift+Tab to move between controls. Buttons, links, disclosure panels, and form fields support standard keyboard interaction.
  • Every page has the same navigation. Company History links to both the changelog and the executive register.
  • Use your browser’s zoom and text-size settings. Content reflows on narrow screens, and keyboard focus remains visible.

Control the ceremonial reading

Pause and resume the output presentation, or reveal the complete result immediately. “Follow new output” is optional, so you can read earlier lines without being scrolled away. These controls affect presentation only; they do not cancel an already submitted numerical mandate.

Reduced-motion and forced-color preferences are supported. Status summaries announce completion and errors without reading every generated line aloud. The output is a named region you can reach with the keyboard.

The Executive Chronicle is a separate, fixed-height scroll region below the numerical output. “Follow new proceedings” keeps its latest entries visible; turn it off to read at your own pace. The ordinal selector opens a stable inspection of a retained record, and “Latest proceedings” restores following. “Inspect paperwork” opens a case-papers dialog; use its close button or Escape to return to the opener.

Verification and scope

Our automated checks cover WCAG A/AA rules, named controls, landmarks, contrast, keyboard interaction, and narrow-screen layouts. We also check expanded API panels, invalid form input, and playback controls. Automated checks do not establish complete conformance; testing with people who use assistive technologies and real screen-reader combinations remains an ongoing responsibility.

The standards reference is W3C’s WCAG 2.2 guidance. See the release validation record for the checks bundled with this release.

Report an access barrier

If a page or control prevents you from completing a task, report an accessibility issue in the repository. Include the page, intended action, browser, and assistive technology if you can. You can also read the original changelog and continuity register as plain text.
